# Rúbrica de Evaluación — Semana 01

> **Semana 01 — Core Components y Flexbox**

## 📊 Distribución de puntaje

| Tipo de evidencia | Peso | Descripción |
| ----------------- | ---- | ----------- |
| 🧠 Conocimiento | 30% | Cuestionario teórico sobre Core Components y Flexbox |
| 💪 Desempeño | 40% | Ejercicios prácticos completados (2 ejercicios) |
| 📦 Producto | 30% | Proyecto de tarjetas adaptado al dominio asignado |

---

## 🧠 Conocimiento (30 pts)

### Cuestionario teórico (30 pts)

| Criterio | Pts | Descripción |
| -------- | --- | ----------- |
| Core Components | 10 | Identifica y describe: `View`, `Text`, `Image`, `ScrollView`, `Pressable` |
| Diferencias web vs mobile | 10 | Explica por qué no existen `div`, `span`, `img` en RN; menciona el bridge/JSI |
| Flexbox en mobile | 10 | Describe `flexDirection`, `justifyContent`, `alignItems`; sabe el default de RN (`column`) |

---

## 💪 Desempeño (40 pts)

### Ejercicio 01 — Core Components (20 pts)

| Criterio | Pts | Descripción |
| -------- | --- | ----------- |
| Pasos completados | 10 | Todos los pasos descomentados y corriendo en Expo Go |
| Sin errores de compilación | 5 | La app carga sin red screens ni errores en consola |
| Comprensión demostrada | 5 | Puede explicar verbalmente qué hace cada componente |

### Ejercicio 02 — Flexbox Layouts (20 pts)

| Criterio | Pts | Descripción |
| -------- | --- | ----------- |
| 4 layouts implementados | 12 | Cada layout se ve igual al diseño de referencia del ejercicio |
| Uso correcto de propiedades | 5 | Usa `justifyContent`, `alignItems`, `flex`, `flexDirection` correctamente |
| Sin posicionamiento absoluto innecesario | 3 | Flexbox es suficiente (no usa `position: 'absolute'` innecesariamente) |

---

## 📦 Producto (30 pts)

### Proyecto — App de Tarjetas (dominio asignado)

| Criterio | Pts | Descripción |
| -------- | --- | ----------- |
| App corre en simulador | 5 | No hay errores al iniciar; se visualiza la pantalla principal |
| Mínimo 3 tarjetas del dominio | 5 | Se muestran al menos 3 elementos coherentes con el dominio asignado |
| Uso de StyleSheet | 5 | Los estilos están definidos con `StyleSheet.create`, no inline |
| Layout con Flexbox | 5 | Las tarjetas tienen estructura correcta usando Flexbox |
| Adaptación al dominio | 5 | Los datos (nombre, descripción, imagen) son coherentes con el dominio |
| Código tipado con TypeScript | 5 | Props e interfaces definidas; sin uso de `any` |

---

## ✅ Criterios de aprobación

- Mínimo **70%** en cada tipo de evidencia (21/30, 28/40, 21/30)
- App funcional en simulador iOS y/o Android
- Entrega puntual antes de la siguiente sesión
- Implementación coherente con el dominio asignado

## ⚠️ Penalizaciones

| Situación | Descuento |
| --------- | --------- |
| Entrega fuera de plazo (por día) | -5 pts del total |
| Código sin TypeScript (uso de `any` generalizado) | -10 pts |
| Dominio igual al de otro aprendiz | Nota 0 en Producto |
| Copia de código de otro aprendiz | Nota 0 en la semana |
- ✅ App funcional en simulador iOS y/o Android
- ✅ TypeScript sin errores de compilación
